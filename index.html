完整性 > 业务逻辑 > 操作效率

DESIGN DECISIONS LOG

本轮做出的重大产品决策。

D1 · 工作区审计：未发现既有 pasay-app.html

本工作区初始为 0 个用户文件。按 brief「继承已确认规则」处理：以 Expense 状态机、Telegram 双语、Owner 审批边界等书面规则为继承基线，未虚构旧文件内容。

D2 · 视觉方向自选 modern-minimal（Linear/Vercel 系）

无活动设计系统、无品牌源。运营工具型界面采用精密中性 + 单一蓝色 accent + oklch 状态色；显示与正文同为系统无衬线（数据密集豁免），数字一律等宽。

D3 · 14 个模块重排为 5 层 IA + 5 个底部导航

首页/物业/任务/租金/支出 常驻底部；租客、支付、导出、设置等低频功能从模块内进入，避免 14 个平级按钮。

D4 · 统一任务引擎 + AI 循环成为产品骨架

审批、付款、跟进、续租、收款全部落成 Unified Task（类型/对象/指派/优先级/截止/下一步/来源）。创建单据即自动生成 Owner/Secretary 任务；完成单据自动闭环任务 — Observe→Action 循环真实可走。

D5 · APPROVED ≠ 完成被做进状态机

批准支出自动创建「付款」任务并进入首页待办；拒绝保留原因入时间线；财务仅确认/逆向，无删除。

D6 · 部分付款数学实时计算

租金状态由已确认金额与应付金额推导，逐笔登记；不会错误变成 PAID（原型内已自动化验证）。

D7 · 权限边界做成可操作交互

Secretary 触发审批/付款/逆向会被拦截并转为 Owner 任务；角色切换即时改变首页队列与语言（Owner 中文 / Secretary English）。

D8 · 学习旅程只影响呈现层

徽章在真实操作后解锁（首笔租金/支出/报修/审批/付款/导出…），不触碰权限、财务与业务状态；下一步建议引导学习。

D9 · 移动优先 + 双端不破版

基准 390×844，容器 430px 上限；桌面为居中设备栏，480px 以下全宽；Telegram WebView 与桌面 Telegram 打开均不破版。

D10 · 本轮明确不做

SaaS merchant console、订阅计费、公开市场、房产销售、CRM、会计 ERP、复杂 BI、NotebookLM、Owner 独立后台、重型游戏化 — 防止范围膨胀。

VNEXT · OPERATION SYSTEM OVERVIEW · PASAY-VNEXT-OPERATION-DESIGN-001

VNext：从"任务待办"到
"AI 负责推进到真实结果的 Operation"

增量设计 · 不推翻已冻结基线
这是一套独立的 VNext 设计层，在已冻结的产品之上原地叠加，不改首页 / Navigation / Quick Actions / Portfolio Pulse / Telegram 产品设计 / 视觉体系 / Rent-Lease 数据模型。VNext 只引入 Operation 作为「AI 必须推进到真实业务结果的容器」，业务对象本身（Property / Tenant / Rent / Expense / Repair）保留不动。
产品层级 · 统一模型
Business Object→Operation→Action / Human Task→Evidence→Verified Result→Closed

Operation = 一件 AI 必须负责推进到真实业务结果的事项。Reminder / Notification / Message / Task 都只是推进手段，不是完成。

双状态模型 · 业务状态 ≠ 执行状态

把「现实发生了什么」和「AI 正在如何推进」拆成两个独立维度，任何一个都不能替代另一个去证明"完成"。

维度反映Rent 示例
Business State现实业务本身UNPAID / PARTIAL / PAID
Execution StateAI 当前推进（互斥核心集）ACTIVE / WAITING_HUMAN / WAITING_EXTERNAL / VERIFYING / BLOCKED / CLOSED · 旁挂 next_actor / next_action / wake_at / escalation_level / priority

Legal Truth 红线：Tenant 口头说付了 ≠ PAID；Secretary 按了"已联系" ≠ Operation 完成；Verification 未过 = 仍在执行。

AI / Secretary / Owner 分工
角色负责绝不负责
AI发现 / 判断下一步 / 准备话术 / 调度 / verify（可信证据自动形成 Verified Result）/ 设 wake_at / 维护 escalation_level无法"完成"任何人工动作；不因发了提醒就算完
