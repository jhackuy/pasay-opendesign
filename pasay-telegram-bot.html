VNEXT · TELEGRAM OVERDUE RENT OPERATION · PASAY-VNEXT-OPERATION-DESIGN-001

Telegram 不是任务后台，
只向真人推送"该他做的动作 / 决策 / 结果"。

独立设计层 · 不重做 Telegram 产品
Telegram 保持冻结定位：AI 员工 + 真人同事协作的办公室。Low cognitive load · 少按钮 · 少打扰 · 最重要动作优先 · 高频确定性 fast path · AI 主动继续被阻塞流程。VNext 只新增「Operation 推进」消息形态，不动固定菜单 / 既有模板。用户可见语言只用自然业务表达（"等待 Paolo 付款 · 8月31日自动检查" / "需要你联系" / "已确认收齐"）；内部枚举仅作设计标注，不暴露给 Owner / Secretary。

Contacted 之后到底发生什么
按下「已联系 / Contacted」绝不等于完成：它只把一次 contact 结果写进 Operation 记录，并按结果推进——拿到承诺日则等待 Paolo 付款（到承诺日自动核对）；没拿到承诺则回到需要你联系。业务态不受影响：没有到账证据，仍是"未付款"，且收集目标不变、不另开新单。
Operation 闭环原则 · Telegram 侧
· 少按钮：每屏最多 2 个确定性动作
· 少打扰：同一 Operation 对同一真人每日主动催办最多一次，除非高风险或新实质事件
· 只报"需要人做的事 / 决策 / 结果"
· AI 主动据 expected_result + deadline + wake_at 续跑，人不需记得回来
· 真正收齐只发生在可信证据核销（Verified Result）后

AI 员工规则 · Expense 侧
· 只报「需要人做的事 / 关键业务变化 / 真正结果 / 异常升级」
· 不暴露 WAITING_HUMAN / VERIFYING / WAITING_EXTERNAL / PAYMENT_VERIFIED 等内部枚举
· 每日对同一真人主动催办最多一次；「我去处理」后不短时刷屏，仅新实质事件 / deadline / escalation 再通知
· 提醒只是推进手段，不能作为 Task / Operation 完成条件
同一业务事实（Mini App 可复现）
